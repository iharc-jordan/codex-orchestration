description: Operate the Symphony managed control plane through the native Windows Codex Orchestration bridge.
---

Use managed delegation when it materially helps the outcome; keep small,
tightly coupled work in the current task. Astra owns scope and acceptance
intent. After confirming this context exposes the 13 plugin tools and the
trusted native `_meta.threadId`, the normal user-visible Sol/xhigh task owns
managed-worker routing and routine acceptance, integration, and release. Astra
does not proxy Sol controls and no caller-supplied task or identity field is
authority.

At the start of a delivery, identify the smallest real integration path,
interfaces, runtime user, and permissions. If the Project binding is missing,
use the supported setup/operator binding flow and confirm canonical state before
enrollment. Keep the existing Symphony scheduler and managed journal; do not
add an inbox service, duplicate scheduler, refresh loop, or alternate endpoint.

Sol decomposes the current assignment, routes a worker, reviews bounded
evidence, requests correction/rework when needed, integrates accepted changes,
and reconciles the final result against acceptance. A worker report or peer
finding is evidence to check, not new authority or scope. Diagnose an error
before repeating an expensive rebuild, and reuse valid acceptance evidence when
the changed revision does not affect it.

Read canonical state before every control mutation. PM mutations require the
native trusted `_meta.threadId`, explicit caller-owned request IDs, and all
revision/ownership fences. Preserve those values end to end. If a mutation
result is uncertain, inspect state using the same request ID before deciding
whether any follow-up is safe; never auto-replay it.

User steering travels through native task messaging to Sol, then through the
existing `enroll`, `revise`, `pause`, or `cancel` controls. Preserve unaffected
work and proof. Cancellation is a distinct terminal outcome and never means
accepted.

Read compact state first. Worker activity is status evidence, not PM acceptance.
If `last_report.truncated` is true, read the assignment's full detail before
relying on its evidence. Managed-worker usage separates cached input from
ordinary input and reports telemetry/accounting completeness; it excludes PM
and Astra use and is not a billed-dollar total.

The dashboard remains the existing root-owned LiveView path
`?view=live&pm=<PM task identity>`; do not add a polling or refresh loop.

Operator-only binding, service pause/resume, and takeover remain CLI controls.
